ReleaseHub（追新）0.7.0 便携版

一、打开软件
1. 右键 ZIP 压缩包，选择“全部解压”。
2. 把 ReleaseHub 文件夹放到可写的位置，例如 D:\TOOLS\ReleaseHub。
3. 双击 ReleaseHub.exe；请保留同目录的 tools 和 integrations 文件夹。
   关闭到托盘后，再次双击同一个 ReleaseHub.exe 即可唤醒原窗口。
4. 若提示缺少 WebView2，请安装微软官方运行环境，或使用 ReleaseHub 安装版补齐。
   https://developer.microsoft.com/microsoft-edge/webview2/

二、添加资源与更新
1. 点击“添加资源”，粘贴 GitHub 项目地址，选择正式版或包含预览版。
2. 选择管理方式：“软件”用于管理安装和版本；“文件”用于保存 PDF、ZIP 等普通文件。
   已有订阅默认保持“软件”方式，也可在资源详情的“项目设置”中切换。
3. 进入“资源库”，切换“软件 / 文件”。右上角可选排序（最近添加、名称升序或降序、最近发布、可更新优先）和“双列 / 三列 / 列表”；重开后保留选择。资源较多时底部可翻页，搜索会查找全部资源。
   右键资源或点击“···”查看详情、检查更新等操作；选中资源后按 Enter 也可查看详情。
   在“···”中选择“屏蔽更新”可暂停该资源的检查、提醒和自动下载；在同一菜单选择“恢复更新”即可重新检查。
   在“可更新”页点击“全部已读”，当前版本仍可下载，但不再显示更新角标或提醒。以后发布的新版照常提醒。
4. 打开资源详情的“发行文件”，核对文件名后点击“下载此文件”。同一版本可分别下载多个附件。
   文件必须来自 GitHub Releases 附件，单个文件最大 4 GiB；不支持任意网盘或网页文件地址。
5. 普通文件只保存，不会安装或自动打开。在“下载”页点击“定位文件”，查看所在目录和校验结果。
   文件状态分为“未下载、已下载、有新版本、文件已移走”。文件缺失时可重新下载，已有文件不会覆盖。
6. 软件包下载完成后，点击更新/安装，无需额外勾选确认。仅在缺少安装目录或 ZIP 根目录时补充选择。
   ZIP 需要明确选择安装包内的程序目录，不会猜测。新版替换同名文件（包括配置），包里没有的原文件保留。
   首装请选择专用空目录。旧受管软件迁移也必须明确选择外部专用空目录，旧位置不会自动删除。
7. EXE/MSI 打开作者的安装向导，并自动跟踪实际安装结果。只有检测到可信的目标版本才同步记录。
   安装器退出或经过一段时间不代表成功；需要重启时等待重启后验证。未识别时可立即检测或一键标记已安装此版本。
   检测任务在重启追新后继续；安装位置、主程序和 Windows 安装记录仅保存在本机，不随订阅导出。
   文件备份不包含注册表、服务等变更，不能保证完整回退安装器。下载完成不等于已经安装。
8. 在软件卡片的“管理备份”中独立开启更新前备份，默认关闭。关闭时不创建完整快照，但保留已有备份。
   开启后保留最近一次成功更新的回退点；恢复或删除直接执行。文件备份不等于完整系统回退。
   未开启备份时更新失败不会自动恢复，目录可能部分更新，请检查后重试。
9. 双击软件卡片打开软件；尚未指定启动程序时，先选择本机 EXE，追新会自动记录所在文件夹，不会立刻启动。
   若已记录的安装目录包含所选 EXE（例如 bin 子目录中的程序），保留原安装目录。再次双击或右键“打开软件”才运行。
   “记录已安装版本”也可选择启动程序并自动填入目录；确认实际安装完成后再保存。
10. 右键资源或在详情中选择“设置备注 / 编辑备注”：标题和描述均可选，描述用较小字号显示。
    有备注时只显示备注、不显示原名称；两项都留空并保存即可恢复原名称。
11. 首页查看更新、下载/待安装和 GitHub 官网动态摘要；“更新”是单独的待处理队列。
12. “下载”可直接删除受管安装包及对应下载记录，保留安装状态和备份；需要时从资源库重新下载。运行中任务不能删除。软件卡片的“管理备份”可直接进入恢复与删除备份入口。

添加已有的本地软件：
- 把本机的 .exe 拖到“资源库 → 软件”空白处或卡片区；也可点右上角“添加本地软件”。
- 软件先入库，追新再在后台识别公开 GitHub 仓库。可靠匹配会关联仓库并检查版本；没有可靠匹配则标记“本地”。
- 点软件卡片“··· → 设置 GitHub 仓库”可补填或更改仓库；有本地程序的条目也可清空链接、保存为仅本地管理。

下载连接与外部下载器：
- “设置 → 更新与下载 → 单文件连接数”可选 1～8，默认 4；不能安全分段的服务器使用单连接。
- 外部下载器默认关闭。在“设置 → 外部下载器”启用“手动下载默认使用外部下载器”，关闭即可恢复内置下载。
- 内置 AB Download Manager 预设使用 http://127.0.0.1:15151/add。先打开 AB 并启用浏览器集成服务，再测试连接。
  测试只读取队列，不添加下载；若 AB 启用了访问密钥验证，当前预设不能发送，请保留验证并改用内置下载。
- 点击下载即发送；真实进度在外部下载器查看。完成后在追新下载页点“导入已下载文件”，校验后再安装。
- 可修改名称、接口地址和 JSON 请求模板以连接其他本机下载器；自动下载仍使用追新内置下载。

三、外观、网络代理和启动偏好
1. 在“设置 → 网络代理”选择跟随系统、手动设置或不使用代理。
2. 手动地址示例：http://127.0.0.1:7890 或 socks5://127.0.0.1:1080。
3. 需要时填代理账号和密码，先“测试连接”，再“保存代理设置”。
4. 新代理用于后续请求；进行中的下载可取消后重新下载。
5. 在“启动与导航”选择默认打开的页面与 GitHub 栏目。
6. 拖动左侧页面调整顺序，也可以选中后按 Alt + 上下方向键。
7. 在“外观”选择浅色、深色或跟随系统；在“配色方案”选择经典蓝、青绿、柔紫或暖琥珀。
   配色与明暗模式分别保存，品牌图标保持经典蓝色。

四、GitHub 授权、分类、备注与动态
1. 进入“GitHub”，点击“登录 GitHub”，复制短码，点击“打开 GitHub 授权页”。
   在 github.com/login/device 核对账号并输入短码，完成后回到追新等待连接。
2. 这是 ReleaseHub 自己的 OAuth 设备短码授权，不借用其他工具的账号；旧版已连接的用户需要重新授权一次。
   授权凭据只保存在本机 Windows 凭据库，不写进便携数据。点击“仅断开追新”不影响其他工具。
3. 进入“Stars”可同步官网 Lists 分类；管理分类时，按页面提示另行授权分类管理权限。
   查看私有仓库也需要主动授权；授权前请阅读 GitHub 显示的权限范围。
4. 点开项目，使用“编辑本地备注”填写名称和短说明；备注保存在追新。
5. “关注动态”显示 GitHub 关注事件；“首页动态”显示官网 Dashboard feed。
6. GitHub 账号面板一起显示 API 授权与官网登录；它们是不同会话，不会用 API 授权冒充网站登录。
   首次点击“连接官网”，在独立 GitHub 官方窗口登录一次；账号不一致时会提示。
7. 官网会话保留在本机，修改无密码代理不会因此清掉登录；只有明确断开、GitHub 会话失效等情况需要重连。
   首页和 GitHub 共享官网动态连接；可刷新、加载更多、查看原文。明确“仅断开追新”也断开本应用的官网会话。
   “查看 GitHub 仓库”在追新内打开仓库详情。可直接加星、订阅，查看项目说明、发行版和已开放的问题或讨论区。
   点击“查看原文”在当前窗口阅读，点“返回”回到原位置。官网原文沿用追新的网页登录；账号授权仍在系统浏览器完成。
   对公开仓库，点“查看最新附件”，再点文件旁的“下载”；不用先订阅。旧版本可点“发行版原文”，在那一版点附件，再选“在追新下载”。进度在“下载”页查看。
8. 页面会先显示本机已有缓存，再尝试更新；网络失败时保留已有内容，并显示更新时间或错误提示。
   页面缓存按账号隔离，最长保留 30 天，总上限 100 MiB，不随便携数据迁移。
9. 可在“设置”中清理页面缓存，订阅和下载文件不受影响。
10. 若代理需要账号密码，官网动态请使用系统代理或无密码的本机转发端口。

风灵月影官网：
- 进入左侧“风灵月影”，点“全部修改器”浏览目录，或在“搜索游戏名称”输入框搜索（可用游戏英文名）。
- 打开游戏页，点官网附件，再点页面上方“另存为…”，选择本机的保存位置。完成后可点“在文件夹中显示”。

五、连接 AI 平台
1. 进入“AI 连接”，开启“开启软件资料连接”。
2. 选择 Claude Code、Codex、Cursor、VS Code 或“通用 JSON”，复制配置到对应平台。
3. 保持追新运行，重新打开 AI 会话。
4. 让 Agent 查询版本、源码、下载错误和安装位置，再在你授权的平台执行编译、安装或修复。
5. 单款软件可在详情中点击“复制资料给 AI”，直接粘贴给 Agent。
6. 命令行由 tools/releasehub-mcp.exe 的 --cli 模式提供，支持 JSON 输出。
完整用法：integrations/AGENT_GUIDE.md。

六、搬到另一台电脑
1. 从托盘菜单选择“退出”。
2. 复制整个 ReleaseHub 文件夹，包括 portable.flag 和 data。
3. 在新电脑打开 ReleaseHub.exe，重新连接账号和配置代理。
软件与文件订阅、备注、偏好、下载文件、历史记录、回退备份和旧受管程序保存在 data 中。
更新到原目录的软件本体仍在其原位置，不会随 data 搬走；新电脑需重新指定真实安装目录和主程序。
本机授权、官网会话、页面缓存与代理密码留在原电脑。
只分享订阅与备注时，使用“设置 → 导出订阅与备注”。

七、常见情况
- GitHub 请求过多：稍后重试，或在 GitHub 页面登录后再检查。
- 网络不通：到网络代理设置测试连接。
- 下载失败：在下载页查看原因并重试，或复制诊断资料交给 Agent。
- 没有合适安装包：先查看“发行文件”；普通附件可以保存，但不能当作软件安装。
  需要自行编译软件时，可在详情复制资料，让外部 Agent 查询源码并编译。
- 文件已移走：在下载页点击“文件缺失？重新下载”；文件仍在原位置时不会覆盖。
- 升级后 GitHub 显示未连接：点击“登录 GitHub”，为 ReleaseHub 重新授权一次。
- 官网动态读取失败：打开官网窗口确认网页账号已登录，再回追新刷新。
