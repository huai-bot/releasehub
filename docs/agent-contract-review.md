# Agent 接入与便携数据的安全边界

这是本项目的实现约束，不是对任意外部 Agent 的能力背书。

## 已采用的设计

- 默认不监听端口；只有用户在设置里开启才启动 `127.0.0.1` 接口。
- 每次请求必须带本机随机访问密钥；密钥保存在 Windows 凭据管理器，不写入便携数据库、导出列表或发行包。
- 便携目录搬到另一台电脑且本机没有对应密钥时，关闭 Agent 接入，等待用户重新开启。
- 拒绝浏览器 Origin 和不匹配的 Host，不开放跨站访问；请求正文和请求频率有上限。
- 路由逐一列出允许的操作，不能把任意 action 透传进桌面命令。没有执行命令、读写任意文件、获取密钥或安装软件的 HTTP 路由。
- HTTP 检查更新强制 `allowAutoDownload=false`，不会触发界面设置中的自动下载。
- 认领任务返回单独的短期票据；后续进度、失败或结果提交都需要这个票据，不能只用 Agent 名称冒领。重启或密钥轮换后旧票据不再有效。
- 构建结果必须说明实际源码提交；有锁定提交时必须一致。结果标为 Agent 构建，不冒充上游正式签名发行，不自动安装。
- GitHub API 授权不转发给下载 CDN。下载来源、重定向、文件名、ZIP 路径和解压规模单独校验。
- 安装器由用户确认后打开；便携程序只放在受管目录。下载完成不等于已经安装。

## 直接检查的重点

缺少/错误密钥、网页跨站调用、伪造 Host、任意 dispatch、无票据汇报、源码提交不符、带凭据的 URL、危险压缩路径、导出文件混入密钥或绝对安装路径。

外部 Agent 运行构建时仍由用户选择环境和权限。ReleaseHub 不读取 DSH 的设置，也不自动调用任何收费模型。
