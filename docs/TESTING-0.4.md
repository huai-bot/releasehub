# 追新 0.4 Windows 本地测试版

## 打开

1. 右键测试版 ZIP，点“全部解压”。
2. 打开解压后的文件夹，双击 ReleaseHub.exe。保留同目录的 portable.flag、tools 和 integrations。
3. 首次运行会在程序旁创建 data。软件记录和偏好保存在这里。
4. 若提示缺少 WebView2，安装[微软官方运行环境](https://developer.microsoft.com/microsoft-edge/webview2/)后再打开。

这是本地编译的 Windows x64 测试包。源码包包含本轮改动，正式发布打包流程仍单独保留。

## 按顺序体验本轮五项改进

### 1. 官网动态连接

进入 GitHub，账号区分别显示“GitHub API”和“GitHub 官网”。点“连接官网”，在弹出的 GitHub 官方窗口登录，再返回追新。进入“首页动态”，随后切到首页，两个页面使用同一动态连接。退出追新再打开，检查官网登录仍保留；如果 GitHub 自己让会话失效，按提示重新登录。

### 2. 仓库与备注

搜索一个仓库，点开详情，编辑本地名称和短说明。列表及详情依次显示备注仓库名、备注描述、原仓库名、原仓库描述。切换栏目后再回来，检查备注和当前浏览位置保留。

### 3. 独立滚动

GitHub 左栏显示分类与筛选，右栏显示仓库内容，两栏分别滚动。较宽窗口打开仓库后，右侧内容区内同时显示列表和详情；较小窗口在右栏显示详情，点“返回列表”返回。把窗口缩到 960×640，分类、账号提示和详情仍可使用。

### 4. 原目录更新、备份与恢复

先用一款可测试的软件副本体验。把它放在专用文件夹，进入资源详情“管理”，记录当前版本及真实软件目录。

1. 下载新版，点击安装／更新，核对原目录、旧→新版本、备份和空间。
2. ZIP 要选择安装包里真正要写入的程序目录，再勾选确认并继续。
3. 新版替换同名文件；安装包没有的旧文件保留。同名配置也会被替换。
4. 进入详情“管理 → 最近一次备份”，确认恢复，检查文件和版本回到更新前。
5. 每款软件保留最近一次成功更新的备份。确认删除备份后，该回退点失效。

首装或旧受管位置迁移必须选择专用空目录。EXE/MSI 会先备份文件，再打开作者安装向导；向导里选择同一原目录，完成后手动记录版本。文件恢复不包含注册表和服务。

### 5. 首页、资源库与安装包清理

首页集中显示更新、下载和待安装事项。资源库改为大卡片，“可更新”是独立队列。软件卡片先选择安装目录内的 EXE，保存后再点“打开软件”。软件卡片的“管理备份”直接打开备份管理。下载页确认删除安装包后，对应下载记录一起删除，已安装软件和回退备份保留。

## 分类缓存与启动预加载

启动后，程序会在后台读取账号状态、仓库、Stars、分类和动态。已连接账号的每个 Stars 分类分别缓存；首次切换没有缓存的分类时显示加载状态，不沿用其它分类的仓库。后台读取失败时，只保留当前分类自己的已读内容。

进入 GitHub → Stars，在“全部 Stars”“未分类”和自建分类之间切换，检查每个分类只显示自己的仓库；再切到“我的仓库”和“关注动态”，检查已预加载内容可直接读取。退出程序再打开，检查缓存先显示、随后后台更新。

Stars 列表读取后，会提前读取仓库分类归属。把鼠标移到仓库或分类按钮，也会优先预读该仓库。再次打开“设置仓库分类”时复用有效缓存，不重复逐个扫描所有分类。保存修改后重新读取相关分类；需要最新结果时点击“刷新分类”。

## 分段下载与外部下载器

进入“设置 → 更新与下载”，在“单文件连接数”选择 1 至 8，默认 4。支持分段的大文件会使用多条连接；小文件或不支持安全分段的服务器使用单条连接。

外部下载器默认关闭。使用 AB Download Manager 时：

1. 先打开 AB Download Manager，并启用它的浏览器集成／接口服务。
2. 在追新设置中保留 AB 预设，点击“测试端口连接”。此按钮只确认端口能连接。
3. 开启“手动下载默认使用外部下载器”，或在资源详情点“外部下载器”。核对链接后确认发送。
4. 在 AB 中查看真实下载进度。追新下载页显示“已交给外部下载器”，不把发送成功当成下载完成。
5. AB 下载完成后，在追新下载页点“导入已下载文件”，选择对应附件。大小和摘要校验通过后，追新复制文件到自己的下载目录，再提供安装操作。原文件保留。

自动下载仍使用追新内置下载。换用其他支持本机 JSON POST 接口的下载器，可修改名称、接口地址和请求模板；接口限定本机地址。发送失败时先检查下载器是否已经收到，再确认重发。

## 资料迁移

退出追新后，复制整个程序文件夹和 data，可带走记录、下载和内部备份。原目录更新的软件本体仍在原位置，不随 data 搬走；外部软件位置不会被程序猜测。API 授权、官网登录和代理密码是本机资料，新电脑需要重新连接。

更多操作见同包 README.txt。
